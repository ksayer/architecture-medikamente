# Анализ текущего состояния (As-Is)

## Проверка текущих мер по защите данных

### Перечень уязвимых точек:

- **Текущий подход к хранению и управлению информацией**  
Все процессы, включая запись на приём, ведение медицинских карт, учёт пациентов, платежей и анализов, осуществляются вручную — данные хранятся в Excel-файлах и отсканированных документах (JPG, PDF).  
Эти материалы размещаются на общем сетевом диске, при этом содержат чувствительную информацию.  
Подход к работе с персональными и медицинскими данными (PII) не соответствует требованиям законодательства РФ.

- **Отсутствие классификации конфиденциальных сведений**  
Практически каждый бизнес-процесс затрагивает персональные данные пациентов: ФИО, дату рождения, контактные данные.  
При расширенной регистрации также собирается дополнительная информация: адрес, место работы или учёбы, наличие хронических заболеваний.  
Эти данные обрабатываются вручную и хранятся в незашифрованном виде, без разграничения по степени чувствительности.

- **Недостаточный уровень защиты конфиденциальной информации**  
Критически важные данные никак не защищаются: отсутствуют средства шифрования, обезличивания и ограничения доступа.

- **Отсутствие контроля действий персонала**  
Всё взаимодействие с информацией — сохранение, чтение и обработка — происходит без централизованного аудита.  
Внутрисистемный обмен данными не отслеживается и не регулируется технически.  
Единственное ограничение основано на логике бизнес-процессов.

- **Недостаточная модель разграничения доступа**  
Доступ к данным регулируется исключительно через доменную авторизацию.  
Дополнительные меры управления правами отсутствуют — сотрудники потенциально могут просматривать информацию, которая им не предназначена.

## Рекомендации по улучшению

- Провести классификацию всех обрабатываемых данных на следующие категории:
  - публичные
  - внутренние
  - конфиденциальные

- Для каждой категории установить соответствующие меры защиты:
  - конфиденциальные — использовать шифрование
  - внутренние — внедрить обфускацию
  - общедоступные — применять обезличивание

- Настроить ролевую модель доступа (RBAC) с интеграцией в инфраструктуру Active Directory

- Определить права пользователей на основе **принципа минимально необходимого доступа** (least privilege)

- Ввести двухфакторную аутентификацию с привязкой к мобильным устройствам

- Настроить системное логирование всех операций и мониторинг движения данных внутри сети

- Реализовать шифрование данных как при передаче, так и при хранении

- Построить централизованную систему для хранения и управления данными

- Обеспечить соответствие архитектуры и процессов нормативным требованиям Российской Федерации в части обработки персональных и медицинских данных

- Ввести механизмы тэгирования данных и автоматизированную проверку обработки чувствительных данных
